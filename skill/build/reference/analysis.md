# 图片客观测量（image_analysis.py）

拆解一张图时，AI 看的是语义（这是什么风格），但有几个维度**看图容易看走眼**：
明度基调、饱和度、色彩关系、边缘密度这些，人眼会被画面的情绪带跑偏，
而且两张图之间的差别靠肉眼很难量化比较。这个工具补的就是这块。

零依赖（只要 Pillow），纯本地，不联网。

```bash
cd ~/Desktop/art-aesthetic-vault/_scripts

python3 image_analysis.py 某张图.jpg          # 可读报告
python3 image_analysis.py 某张图.jpg --json   # 机器可读
python3 image_analysis.py ./某个目录 --json   # 批量
```

投递箱扫描已经默认接上了它，跑 `ingest_inbox.py --scan` 就会带上这些维度。
不想要就加 `--no-analysis`。

## 七个维度

### 明度 Luminance

| 字段 | 含义 |
|---|---|
| `mean` `std` `median` | 灰度均值、标准差、中位数 |
| `dynamic_range` | 实际用到的动态范围（截掉首尾 0.5% 后） |
| `key` | 明暗基调：低明调 / 偏暗 / 中间调 / 偏亮 / 高明调 |
| `highlight_clip_pct` `shadow_clip_pct` | 高光/暗部溢出的像素占比 |

**溢出的百分比很关键**：巴洛克那种「深压的黑」会让暗部溢出很高，
而高明调日系插画高光溢出高。溢出高说明这是有意为之的风格，不是曝光失误。

### 对比 Contrast

- `rms` RMS 对比度（标准差）
- `michelson` 迈克尔逊对比度 `(max-min)/(max+min)`
- `level` 分级：极低 / 低 / 中等 / 高 / 极高

### 色彩 Color

- `mean_rgb` 平均 RGB
- `temperature` + `warm_score` 色温倾向（暖 / 中性 / 冷，分数越正越暖）
- `saturation` 平均饱和度
- `dominant` 量化主色（hex + 占比）

### 和谐 Harmony ← **换过三版，看下面的踩坑**

- `scheme` 色彩关系：单色调 / 邻近色（有限调色板）/ 互补·两组色相对峙 / 中等多色 / 多色相
- `concentration` 色相集中度 R（0=色相均匀散布，1=单一色相）
- `effective_hues` 有效色相数（色相直方图的 exp(熵)）
- `mean_hue` + `mean_hue_name` 主色相角度与中文色名
- `colored_ratio` 有色像素占比（低 = 画面接近灰调）

### 构图 Composition

- `thirds_energy` 三分交点区域的能量，与 `overall_energy` 比较
- `subject_on_thirds` 主体是否落在三分交点
- `symmetry_hint` 对称性：对称 / 近似对称 / 非对称
- `center_weight` 中心与全图的能量比（>1 表示中间重、边缘轻，即暗角/向心构图）

### 质感 Texture

- `edge_density` 边缘密度（Sobel 幅值超阈值的像素占比）
- `local_variance` 局部方差
- `entropy` 灰度直方图熵
- `busyness` 繁杂度：极简 / 简洁 / 中等 / 繁杂 / 极繁

### 线条 Lines

- `orientation` 主导方向：以水平线为主 / 以垂直线为主 / 以对角线为主 / 无显著方向
- `dominant_angle` 梯度方向直方图的峰值角度
- `strong_edge_pct` 强边缘占比

## 怎么用这些数字

**数字是信号，不是结论。** 实测过：纯按配色距离匹配，
一张油画被算成最接近「现实主义」，但那只是土色系重合，风格毫不相干。

正确的用法是**交叉验证**：

1. 先看图，凭感觉判断风格方向
2. 再看数字，检查有没有看走眼的地方
3. 数字和感觉冲突时，回去看图 —— 通常是感觉错了

真实例子（本库的图）：

| 图 | 测量 | 结论 |
|---|---|---|
| 巴洛克受难图 | 明度 43.4「低明调」+ 线条 135° 对角线主导 | 对上流派卡里的 tenebrism 和 diagonal composition |
| 神奈川冲浪里 | 集中度 0.20，主色相蓝 203°，判「互补·两组对峙」 | 普鲁士蓝 vs 米黄纸底，正是这张版画的色彩骨架 |
| 色调主义园林 | 饱和度 0.156，有效色相 1.80，判「单色调」 | 对上「低饱和、统一色调」 |
| 大津绘画卷 | 主色按面积是米黄 37%，和谐判蓝 203° 互补 | 纸底与颜料的对峙——**两个信号互补，都不该丢** |

最后一行是重点：主色（按面积）和和谐（按色相集中度）**测的不是一回事**，
一个说「画面大部分是米黄」，一个说「真正的颜色是蓝」。
两个都留着，比强行合成一个数有用。

## 踩过的坑

### 和谐维度不能用「量化主色」算

第一版：取量化主色，两两算色相距离，平均。
结果**任何图都被判成「邻近色」** —— 量化出来的那几个色都接近画面均值色，
距离天然就小，完全没有区分度。

### 也不能「找色相峰 + 固定阈值」

第二版：色相直方图找峰值，超过最高档 45% 的算显著，峰值间距定量阈值。
问题在**面积和饱和度互相打架**：

- 阈值低了 → 大津绘的米黄纸底（占满画面，饱和度约 0.2）压掉蓝和服
- 阈值高了 → 色调主义整张归零（它本来就只有极低饱和的橙黄）

这是死路，调不出来的。

### 最终版：圆统计量

不做峰值猜测，直接算两个稳的量：

- **R** 色相向量的圆集中度 `|Σ w·e^{iθ}| / Σw`
- **eff** 色相直方图的 `exp(熵)`，即真正参与画面的色相个数

好处是 `R` 低而 `eff` 不高能直接抓出**两组色相对峙（互补）**，
这正好是峰值法漏掉的情况（冲浪图 R=0.20 但 eff 只有 3.59）。

权重用 `s²` 而不是 `s`，进一步压制低饱和底子。
饱和度地板 0.15、明度地板 0.12，低于此的像素不参与（接近灰/黑的不算色相）。

### 图像缩小到 256 就够

`ANALYZE_SIZE = 256`。再大只是变慢，指标几乎不变 —— 这些统计量本来就抗缩放。

### Sobel 不用 numpy

用 `ImageFilter.Kernel` 实现，所以这个脚本**只要 Pillow**，
不需要 numpy/opencv。T2 的那些增强（人脸、霍夫直线）才需要，而且是可选的。

### `render()` 的 `compact` 参数

投递箱扫描自己已经印了尺寸和主色，所以调 `render(r, compact=True)`
省掉那两行，不然会重复。

## 可选的三个增强维度（image_analysis_ext.py）

上面七项**只要 Pillow**，永远可用。下面三项要 numpy / opencv，
所以单独一个文件、**优雅降级**：装了多三项，没装主脚本照常跑。

```bash
python3 image_analysis_ext.py 某张图.jpg        # 单独跑增强维度
ARTVAULT_NO_EXT=1 python3 image_analysis.py ... # 全局关掉增强
```

装依赖（本仓库已经把依赖放在 `_scripts/vendor/libs`，下面这条是给外部用户）：

```bash
pip3 install --target ./vendor/libs numpy opencv-python-headless
```

### 人脸 / 景别

`count` 检出数、`largest_face_pct` 最大脸占比、`positions` 位置、`framing` 景别。

景别对提示词是硬信息 —— `close-up portrait` / `half body` / `full body`
出图差别极大，而「画面里有几张脸」人眼容易数漏（群像里的侧脸、远景小脸）。

分档：`>45%` 特写 / `>22%` 半身 / `>9%` 大半身中景 / 否则远景全身 /
≥3 张脸且都小于 18% → 群像。

实测：伦勃朗《Tieleman Roosterman》脸占画面高 13.6% → 判「大半身 / 中景」，
看图确认是可见到膝的大半身像，对得上。

**局限要说清**：Haar 只认正面，对绘画/风格化的脸不敏感。
实测 8 张明确人像检出 6 张，漏的是侧面和光照怪异的两张。
所以输出写的是「检出 N 张」而不是「有 N 个人」。

### 直线（霍夫）

`count` 去重后的直线数、`horizontal`/`vertical`/`diagonal`、`raw_segments` 原始段数。

和主脚本 `lines` 维度的分工：
- 主脚本 `lines` 用梯度方向直方图，测**整体纹理走向趋势**（笔触方向、画面大势），不需要真有一条直线
- 这里的 `hough` 测**确实存在的线段**

印象派的碎笔触会拉高主脚本 `lines`，但霍夫可能一条都检不出 —— 这就是两者的用处差异。

实测语义正确：

| 图 | 结果 |
|---|---|
| 蒙德里安式构图 | 11 条，水平 7 / 垂直 4 / **斜向 0** |
| 精确主义摩天楼 | 10 条，**9 条垂直** |
| 色调主义园林 | 0–2 条 |
| 大津绘画卷 | 15 条，11 条水平（画卷格纹边框 + 接缝，真实存在） |

### 显著性

`center_x`/`center_y` 视觉重心、`main_region` 最大显著区占比、
`top5_mass` 最显著 5% 像素的质量占比、`focus` 集中度判定、`peak_on_thirds`。

谱残差法（Hou & Zhang, CVPR 2007），原理是自然图像的对数幅度谱大致平滑，
减去平滑部分剩下的「残差」对应视觉上意外/突出的区域。**只需 numpy FFT**，
不需要 opencv（`cv2.saliency` 在 opencv-python-headless 里根本没有，是 contrib 模块）。

实测 `main_region`：单人肖像 47%、繁杂版画 8%、均匀风景 5%。

## 增强维度的坑

### 人脸不能缩到 256 检测

第一版复用了主脚本的 256px 图做人脸检测，**三张图全部 0 张**。
Haar 级联的基特征是 24x24，脸缩到 40px 就基本检不出。

实测同一张 900px 肖像：缩到 256 → 0 张，缩到 512 → 0 张，
用长边 800 + `(scaleFactor 1.08, minNeighbors 5, minSize 28)` → 检出。

所以人脸这一项**单独读原图**，不复用 256px 版本。主脚本的
`analyze()` 因此把原图 `im` 也传给了 ext 模块。

### 霍夫 `threshold=45` 会把噪声当直线

第一版 `threshold=45, minLineLength=0.18×短边, maxLineGap=6`，
一张色调主义风景报出 **112 段「斜线」** —— 全是 Canny 噪声和同一条边被反复检出。

改为 `threshold=80, minLineLength=0.25×短边, maxLineGap=3`，
再做**共线合并**（角度差 <6° 且 rho 差 <10px 算同一条），
同一张图降到 2 条。`raw_segments` 字段保留了原始段数便于对照。

### 「显著分布的方差半径」没有区分度

第一版用「显著分布相对重心的方差半径」当集中度，四张图全在 0.67~0.83，
看着像都「分散」，其实毫无区分度。

原因是**谱残差图是边缘型的**：全图各处都有小峰（每个物体轮廓都是），
方差被这些小峰撑满，跟「有几个主体」没关系。

换成两个真能量集中度的量就分开了：`top5_mass`（最显著 5% 像素占多少质量）
和 `main_region`（最大连通显著区占显著总面积的比例，用 `cv2.connectedComponents`）。

## 和 T3 视觉特征的关系

这个脚本测的是**可解释的客观维度**——每一项都能翻译成提示词
（「低明调」→ `low-key lighting`，「繁杂」→ `intricate detail`）。

`_scripts/vision/` 下的 T3 是另一回事：用 macOS Vision 框架提取 768 维特征向量，
做的是**语义相似度检索**（「找和这张最像的图」），向量本身不可解释。

两者互补：这套给拆解用，T3 给找参考图用。

### 但「用客观维度做图像→流派匹配」实测不如 Vision

曾以为「明度/饱和/笔触正是艺术史划分流派的依据」，所以用这 31 维建流派指纹
应该比 Vision 强。实测**相反**（`movement_fingerprint.py`，400+ 张、78 个流派、
排除 pinterest 投递箱，留一法）：

| 特征 | 最近邻同流派 | 72 选 1 Top-1 | 随机基准 |
|---|---|---|---|
| Vision（768 维） | **27.6%** | **30.6%** | ≈1% |
| T1 客观维度（31 维） | 13.4% | 13.2% | ≈1% |

两者都是随机水平的十几到二十几倍，都含真实信号；但 Vision 在两个口径上都是
约 2.3 倍。可能的原因：31 维里含大量与流派无关的信息（画面比例、对称性、
边缘密度更多受题材和构图支配）。

**基准一定要算对**：这里的「随机」是「随便挑另一张图恰好同流派」，本库约 1%。
不是 50% —— 曾经用 50% 当基准，得出过「44% 近乎随机」的相反结论，
而且那个 44% 还被 `pinterest/` 投递箱（212 张混杂图互相成为最近邻）抬高了。

**两者都只是建议**：Top-1 三成意味着十次错七次。真要判风格，以库里的流派卡为准
（`artvault.py layers <流派>` 是人写的具体术语，比任何像素统计可靠）。
